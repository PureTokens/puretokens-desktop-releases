# Pure Tokens Switch 0.3.0

客户端配置、会话恢复与加载体验更新。以下记录本版本的最终行为；安装包与真实客户端验收仍按双设备清单执行。

- 完善失败详情的敏感内容过滤，覆盖凭据、网络地址、宿主路径及诊断正文。

- 操作结果提示改为窗口右上角显示，长文字可自动换行；移除必选分组自动纳入的重复说明。

- 使用记录的排查提示移至统计卡片上方，移除顶部重复的空记录说明。

- 移除 Fast 开关正常状态的悬停长提示，保留异常反馈。

## 客户端配置

- 操作提示改为清晰白底、锯齿色条和圆形状态图标，以绿、橙、红、蓝区分成功、警告、失败与信息，并提供加粗状态标题。

- 重启期间阻止重复点击，本机拒绝同一客户端的重复启动请求，并增加 3 秒冷却。

- 操作提示显示在窗口右上角，长消息自动换行，保留去重和必要恢复动作。

- 兼容 ChatGPT 新版嵌套模型设置结构，修正增强启动兼容性错误被覆盖的问题；Windows 26.903.8094.0 实机验证待完成。

- 新增 Pi Coding Agent：支持检测、一键配置、预览、恢复和终端启动。仅管理 Pure Tokens 模型服务商，保留个人认证及设置；应用后在 Pi 的 `/model` 中选择模型。暂不支持会话管理。

- 底部仅显示当前需要的一项操作：一键配置或重启客户端；配置核对一致后才显示重启。
- 重启按钮改用统一箭头图标，并明确显示要重启的客户端名称。
- 增强启动等待 ChatGPT 首次页面加载完成后再刷新，页面失效或超时则停止增强，避免打断首次加载；本次修复仍待双设备实机验收。

- 使用记录在统计卡片上方显示模型广场排查提示，长提示单行手动滚动。
- 一键配置与重启按钮图标统一为 20.8px，按钮和文字尺寸不变。
- 增强设置移至“可用模型”下方的点击弹窗，底部统一重启按开关选择增强或普通启动；未应用的配置需先一键配置。
- 使用分组以倍率后的锁图标标识不可取消的分组，移除“必选”文字。
- 失败使用记录详情展示脱敏后的具体失败原因，便于定位请求错误。
- 使用记录查询时显示 loading 遮罩，完成或失败后自动关闭。
- 底部操作按钮统一倾斜圆角立体样式：重启鲜绿色（`#4cc70c`）、一键配置主题主色并带刷新图标。
- 修复所有客户端首次创建 Key 可能报错、再次点击才成功的问题；创建流程使用本次插入的准确 ID，避免同名 Key 混淆。
- 修复切换增强开关后悬浮设置面板意外关闭，可连续调整 Fast 和插件市场。
- 优化增强启动确认提示，明确重启原因和回答中断影响。
- Qoder 支持一键配置、预览、更新和恢复，保留其他服务商及设置。应用后重启 Qoder，再从自定义模型中选用。暂不支持会话管理。

- 新增 Kimi Code：检测安装、配置预览、应用/恢复与终端启动；支持 `KIMI_CODE_HOME`，保留原有登录和个人设置。Moonshot 分组为必选，按模型协议配置主模型和辅助模型；辅助任务统一使用自动默认模型。会话管理暂不支持，真实模型和 Windows 真机验收尚未完成。

- 十三个客户端统一展示与检测：ChatGPT、WorkBuddy、DSH Desktop、ZCode、Claude Code、Grok Build、Gemini CLI、OpenCode、Kimi Code、Qoder、Pi、Claude Desktop、Trae。十二个客户端使用受管配置；Trae 使用应用内手动配置。卡片右上角以贴角角标区分桌面端和命令行。
- 每个客户端的原生供应商分组自动选中，以倍率后的锁图标标识且不可取消；清空只移除额外分组。旧配置缺少必选分组时自动补选，正式应用后才同步到宿主。必选分组不可用或没有兼容文本模型时阻止应用，不以其他供应商替代。Claude Desktop 只允许 Anthropic 分组。
- 默认模型按客户端供应商规则自动选择首个兼容文本模型，字段禁用，不能单独手选；Codex 仅纳入已验证兼容模型。ZCode 保留在客户端内部选择模型，不写全局默认模型。
- 新增 Claude Desktop 三方模式配置：管理 `Claude-3p` 下的配置、配置库索引及 Pure Tokens 专属 Profile，保留 MCP 和其他 Profile；修正 macOS 应用标识，使尚未创建三方配置目录的已安装应用也能被识别。
- 新增 DSH Desktop 接入：管理 Harness 的 `settings.yaml` / `.credentials.yaml` 中 Pure Tokens Provider、默认模型和受管凭证引用，保留其他设置。Unix 原子写入使用 `0600`，避免凭据权限导致宿主启动失败。
- 新增 ZCode 接入：在 `~/.zcode/v2/config.json` 的 `provider.puretokens` 写入所选文本模型，支持 `ZCODE_DATA_BASE_DIR`，保留其他 Provider 和会话选择。旧格式需先由 ZCode 自行迁移；恢复仅移除可确认归属的受管 Provider。ZCode 受管 Key 分组更新需要配套的 Product BFF 修复。
- 新建受管 Key 使用“客户端 ID-8 位随机后缀”；旧 Key 保持名称并继续复用。连接区使用 140px 标签列，地址和掩码 Key 分别置于只读输入框，框内提供复制图标，不提供 Key 查看入口。
- 应用确认弹窗显示去重后的模型总数、图片、视频及实际写入模型清单，写入结果来自 Native 预检。Skills 安装提示词置于数量卡片上方并提供复制；媒体模型通过 Skills 调用，不出现在客户端模型列表。弹窗正文可滚动，确认操作保持可见。
- 启动和重新聚焦时，仅在本地应用记录、文件哈希及当前选择一致时恢复“重启客户端／在终端中启动”；不一致要求重新应用，读取失败提供重新检测。核对不发送模型请求。
- 重启入口统一保留在底部操作栏，按钮上方常驻浅绿引导气泡；重启成功后仍提示新建会话，终端菜单展开时直接覆盖原位气泡。按钮统一尺寸；重启使用统一箭头图标，大小与一键配置图标一致，文案明确显示“重启 + 客户端名称”。

## Codex 增强与会话

- Fast 与插件市场开关位于“可用模型”下方点击打开的增强设置弹窗；底部统一重启按已保存选择启动。入口与弹窗显示运行状态，后台失败和断线可见；不提供独立增强启动／停止按钮或快捷方式创建，已有用户快捷方式不会被自动删除。
- 增强根据当前安装资源的结构与启动时一致性判断兼容性，不使用桌面版本号或固定资源哈希白名单；仅连接本次启动的独占本机端口，不接管普通 Codex。Windows 为预览支持，仍需真机与安装包验收。
- Codex 输入区提供紧凑 Fast 开关，仅影响当前本机会话的新回复，可选 Fast／Standard；遵守宿主管理策略及模型能力。提交成功不代表服务端优先处理已验证，不自动重试模型请求，不持久化正文或凭据。
- 会话管理位于“可用模型”下方，使用无图标的紫色虚线文字按钮；以当前客户端宽弹窗提供搜索、预览、删除确认和支持的恢复操作，右上角关闭并保留配置页状态。
- ChatGPT/Codex 支持保守修复完整旧格式会话的缺失索引与失效路径，先备份本地索引，再事务写入；损坏、信息不足和冲突分别报告，失败整批回滚。完成后仍须重启宿主验证。
- Claude Code、Gemini CLI、OpenCode、Grok Build 支持确认后在原始项目目录恢复已验证活动会话；Native 重新校验引用并使用固定启动参数，不发送新提示词。终端交接成功不等于会话恢复已验收。

## 账户、界面与可靠性

- 修复 ZCode 用量筛选在 Product BFF 与 New API 两层遗漏的问题，兼容新旧受管 Key 名称并保持服务端分页；需要加载配套服务端更新后生效。

- 登录使用独立的非凭据安装实例 ID；配套 BFF 为同账户同实例轮换会话，保留其他设备。Cookie／密码仍仅存 Native 内存，完全退出后需重新登录；退出尝试有界注销，登录身份核对失败撤销新会话。
- 登录页公开服务信息读取失败后按有上限的退避间隔继续重试；联网、重新聚焦或从托盘恢复时可立即重试。服务端明确关闭密码登录时不按网络故障重试。修复 Windows 最小化到托盘的闪烁／重新显示问题。
- 操作成功、失败与警告统一使用去重 Toast，可携带恢复动作；服务范围、供应商与页面固有说明仍保留在原位置。预检和 API Key 准备失败提供更明确的阶段提示。
- 主窗口默认及最小尺寸为 1440×840，内容随窗口展开；提示词与免费资源直接置于顶部导航，常见问题位于最后，“AI 漫剧”为不可点击的即将上线入口。
- 统一导航页面、用量、FAQ、模型和内容卡片加载骨架，刷新客户端目录时保留已有内容。Skills／提示词图片使用紧凑方形容器、完整等比展示，不裁切或悬停放大；模型／供应商图标与 Web 对齐。
- 免费资源图片使用独立无 Cookie 公共读取链路；使用记录列表及详情统一显示电脑本地时间。托盘刷新合并重叠请求，限制分组模型补全并发，清理持续增长的缓存失效记录，并在读取期间限制过大 API 响应。
- 更新失败区分清单、下载、校验和安装阶段，保留当前版本并提供官方下载入口；静态灰度清单不可读取时回退同一 Stable 的发布清单，仅短暂下载故障重试一次，校验或安装失败不重复替换。
- 修复 Windows WorkBuddy、ZCode 测试路径和临时 HOME 的 Roaming AppData 夹具。同步十三客户端验收范围、协议证据范围与本版本最终说明，移除互相矛盾的旧交互描述。隔离测试通过不代表安装包、真实宿主或计费模型请求已经验收。
